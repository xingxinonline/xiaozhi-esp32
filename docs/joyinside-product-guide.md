## 产品概述

JoyInside 是京东推出的实时语音对话协议，支持低延迟、高质量的人机语音交互。本项目将 JoyInside 协议移植到 ESP32-S3 平台，实现了完整的语音唤醒、实时对话、TTS 播放等功能。

蓝豆包是基于立创实战派 S3 简化设计的开发板，去掉了屏幕接口、摄像头和 PCA9557 扩展，保留了核心的音频编解码功能，适合纯语音交互场景。

### 硬件平台

| 组件     | 规格                   |
| -------- | ---------------------- |
| 主控     | ESP32-S3 (双核 240MHz) |
| 音频输入 | ES7210 4通道 ADC       |
| 音频输出 | ES8311 DAC + PA        |
| 状态指示 | LED (GPIO48)           |
| 用户按键 | BOOT 键 (GPIO0)        |
| 存储     | 8MB Flash + 8MB PSRAM  |

### 核心特性

- ✅ **离线唤醒**：本地 WakeNet 模型，无需联网即可唤醒
- ✅ **实时对话**：云端 VAD + ASR，支持自然对话
- ✅ **低延迟 TTS**：流式播放，边下载边播放
- ✅ **打断功能**：说话即可打断 TTS 播放
- ✅ **连续对话**：唤醒后可直接说内容，无需等待
- ✅ **预连接**：启动时预先建立 WebSocket，唤醒后零延迟
- ✅ **自动重连**：网络断开后自动重连，支持状态提示音
- ✅ **LED 状态指示**：通过 LED 指示当前工作状态
- ✅ **单按钮控制**：短按音量、双击减音量、长按对话

## 核心功能

### 1. 语音唤醒

使用 ESP-SR 的 WakeNet9 模型进行本地唤醒词检测。

| 参数     | 值         |
| -------- | ---------- |
| 唤醒词   | "你好东东" |
| 检测延迟 | < 100ms    |
| 误唤醒率 | < 0.5次/天 |

### 2. 语音识别 (ASR)

采用云端流式 ASR，支持实时识别和最终结果。

```
用户说话 → Opus 编码 → WebSocket 发送 → 云端 ASR → 实时/最终结果
```

### 3. 语音合成 (TTS)

流式 TTS 播放，支持预缓冲和打断。

| 参数     | 值                            |
| -------- | ----------------------------- |
| 采样率   | 16kHz (服务端) → 24kHz (播放) |
| 编码格式 | Opus                          |
| 预缓冲   | 2 帧 (120ms)                  |

### 4. 对话状态管理

```
IDLE → LISTENING → PROCESSING → SPEAKING → IDLE
  ↑                                          |
  └──────────────────────────────────────────┘
```

| 状态        | 说明                    |
| ----------- | ----------------------- |
| IDLE        | 空闲，等待唤醒          |
| LISTENING   | 聆听中，上传音频        |
| PROCESSING  | 处理中，等待 Agent 响应 |
| SPEAKING    | 播放 TTS                |
| INTERRUPTED | 被打断（临时状态）      |

## 交互时序

### 完整对话时序

```
时间轴 (ms)
    │
    │  用户说 "你好东东，今天天气怎么样"
    │
  0 ├─── WakeNet 检测到唤醒词
    │
    │    [并行执行]
    │    ├── 启动唤醒词 Opus 编码 (异步)
    │    ├── 验证预连接 (SendPing)
    │    └── 如需要，建立新连接
    │
200 ├─── 编码完成，开始发送唤醒词音频
    │
300 ├─── 切换到 LISTENING 状态
    │    继续上传实时音频
    │
    │    ... 用户继续说话 ...
    │
800 ├─── 服务端: ASR 识别中
    │
    │    ... 用户说完 ...
    │
1500├─── 服务端: VAD 检测到静音
    │
1800├─── 收到 ASR Final: "你好东东今天天气怎么样"
    │
2000├─── 收到 CALL_AGENT_START_EVENT
    │    切换到 PROCESSING 状态
    │
    │    ... Agent 处理中 ...
    │
2500├─── 收到 TTS_SENTENCE_START
    │    切换到 SPEAKING 状态
    │    开始预缓冲 TTS 音频
    │
2620├─── 预缓冲完成 (2帧/120ms)
    │    开始播放 TTS
    │
    │    ... TTS 播放中 ...
    │
5000├─── 收到 TTS_COMPLETE
    │
5200├─── TTS 播放完毕
    │    切换到 IDLE 状态
    │    启动空闲超时计时器 (120秒)
    │
```

### 打断时序

```
时间轴 (ms)
    │
    │  TTS 正在播放...
    │
  0 ├─── 用户开始说话
    │
 50 ├─── 云端 VAD 检测到语音
    │
100 ├─── 收到 INTERRUPT 事件
    │    ├── 停止 TTS 播放
    │    ├── 清空解码缓冲
    │    └── 切换到 LISTENING 状态
    │
    │    继续新一轮对话...
    │
```

### 连续唤醒时序

```
时间轴 (ms)
    │
    │  用户说 "你好东东今天几号"（连续说，不停顿）
    │
  0 ├─── WakeNet 检测到 "你好东东"
    │
200 ├─── 开始发送音频（包含唤醒词+后续内容）
    │
500 ├─── 服务端收到 INTERRUPT（检测到持续语音）
    │
    │    ... 用户继续说 ...
    │
1200├─── ASR Final: "你好东东今天几号"
    │    （唤醒词和内容一起识别）
    │
```

### 网络断开重连时序

```
时间轴 (ms)
    │
    │  WiFi/WebSocket 连接断开
    │
  0 ├─── 检测到连接断开
    │    ├── 播放警告提示音 ⚠️
    │    ├── 停止当前 TTS 播放
    │    ├── 重置对话状态
    │    └── 设备进入 IDLE 状态
    │
    │    ... WiFi 重连中 (自动) ...
    │
15s ├─── WiFi 重连成功
    │    触发协议预连接
    │
16s ├─── WebSocket 连接成功
    │    ├── 播放成功提示音 ✅
    │    └── 恢复就绪状态
    │
    │    设备可正常使用
    │
```

> 💡 **说明**：网络断开时会立即播放警告音通知用户，重连成功后播放成功音。整个过程自动完成，用户无需干预。

## 使用技巧

### 💡 最佳实践

1. **连续对话**
   - 说完唤醒词后可以直接说内容，无需等待
   - 例如："你好东东今天天气怎么样" 一口气说完

2. **快速打断**
   - TTS 播放时直接说话即可打断
   - 打断后立即进入聆听状态

3. **单按钮控制（BOOT 键）**
   - 短按：音量 +10%（到顶循环回 10%）
   - 双击：音量 -10%（最低 0%）
   - 长按：开始/停止对话
   - 启动时短按：进入配网模式（未连接 WiFi 时）

4. **空闲超时**
   - 对话结束后 120 秒自动断开音频通道
   - WebSocket 连接保持，下次唤醒秒连

### ⚡ 延迟优化

| 优化项         | 效果                                |
| -------------- | ----------------------------------- |
| 预连接         | 启动时建立连接，唤醒后无连接延迟    |
| 关闭唤醒词发送 | 省去 200-530ms 编码时间             |
| 唤醒提示音     | 播放"叮"声反馈，AEC 自动过滤        |
| TTS 预缓冲     | 2-3帧 (120-180ms)，平衡延迟和流畅度 |
| 心跳保活       | 15秒心跳，保持连接活跃              |

## 配置说明

### Kconfig 配置项

```kconfig
# 启用 JoyInside 协议
CONFIG_USE_JOYINSIDE_PROTOCOL=y

# 发送唤醒词数据（推荐关闭以获得最低延迟）
CONFIG_SEND_WAKE_WORD_DATA=n

# 唤醒词缓冲时长（仅当发送唤醒词时生效）
# 可选：500ms、750ms、1000ms、1500ms、2000ms
CONFIG_WAKE_WORD_BUFFER_1000MS=y

# Bot ID
CONFIG_JOYINSIDE_BOT_ID="your_bot_id"

# 认证方式 (AK/SK)
CONFIG_JOYINSIDE_AUTH_AK_SK=y
CONFIG_JOYINSIDE_ACCESS_KEY="your_access_key"
CONFIG_JOYINSIDE_ACCESS_KEY_SECRET="your_secret_key"
CONFIG_JOYINSIDE_VENDOR_ID=100090

# 心跳间隔 (毫秒)
CONFIG_JOYINSIDE_HEARTBEAT_INTERVAL_MS=15000

# 空闲超时 (秒)
CONFIG_JOYINSIDE_IDLE_TIMEOUT_SEC=120

# TTS 预缓冲帧数
CONFIG_JOYINSIDE_PREBUFFER_FRAMES=3
```

### 唤醒词发送配置

| 配置            | 延迟影响   | 提示音     | 说明                             |
| --------------- | ---------- | ---------- | -------------------------------- |
| **关闭** (推荐) | ⚡ 最快     | 播放"叮"声 | 不发送唤醒词，直接上传实时音频   |
| 开启            | +200~530ms | 无         | 发送唤醒词缓冲区后再上传实时音频 |

> 💡 关闭唤醒词发送时，设备会播放提示音反馈唤醒成功。AEC 会自动过滤提示音，不影响语音识别。

### 时区配置

默认配置为中国时区 (UTC+8)：

```c
// 在 JoyInsideInitSntp() 中设置
setenv("TZ", "CST-8", 1);
tzset();
```

## 注意事项

### ⚠️ 已知限制

1. **采样率不匹配**
   - 服务端 TTS 输出 16kHz
   - 设备播放 24kHz
   - 需要重采样，可能有轻微失真

2. **网络要求**
   - 需要稳定的 WiFi 连接
   - 建议 RSSI > -70dBm

3. **内存占用**
   - WakeNet 模型约 1MB
   - AFE 处理约 500KB
   - 建议使用带 PSRAM 的模块

### 🔒 安全建议

1. **Access Key 保护**
   - 不要将 AK/SK 硬编码到代码中
   - 使用 NVS 加密存储
   - 定期轮换密钥

2. **Token 管理**
   - Token 有效期 8 小时
   - 自动刷新机制已实现
   - 监控 Token 过期告警

## 故障排查

### 常见问题

#### 1. 连接失败

```
E (xxx) JoyInsideAuth: HTTP POST failed
```

**解决方案**：
- 检查 WiFi 连接
- 验证 AK/SK 配置正确
- 检查系统时间是否同步

#### 2. SSL 错误

```
E (xxx) Dynamic Impl: mbedtls_ssl_fetch_input error=76
```

**解决方案**：
- 预连接可能已断开
- 系统会自动重连
- 检查网络稳定性

#### 3. TTS 播放卡顿

**可能原因**：
- 网络延迟过高
- 预缓冲不足
- 解码性能不足

**解决方案**：
- 增加预缓冲帧数
- 检查网络质量
- 优化解码任务优先级

#### 4. 唤醒词识别不灵敏

**解决方案**：
- 检查麦克风连接
- 调整输入增益
- 确保环境噪音不太大

### 调试日志
